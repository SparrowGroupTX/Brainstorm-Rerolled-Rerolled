## Measurement contract

`Advisor/performance.lua` is opt-in through the existing public-recording preference. It uses finite monotonic elapsed wall times, fixed-label counters/histograms, at most eight slow-frame examples and32 decision receipts per window. Histogram upper boundaries are0.001,0.004,0.008,0.016,0.033,0.05,0.1,0.25,1 and5seconds, plus overflow. A frame is eligible for a slow example when its update or start-to-start interval is at least0.1seconds; the eight largest are retained with an explicit truncation count. Further decision receipts increment their own dropped counter. It emits no more than one compact `performance_window` summary per five seconds, with explicit empty public context. Ordinary frames accumulate scalars; telemetry performs no solver call and adds no per-frame snapshot or disk write.

Measured regions include original `Game:update`, checkpoint/search/journal/advisor/auto/legacy update subphases, update total and frame gap; original draw, advisor HUD draw and draw total; snapshot capture, fingerprint construction, refresh/presentation, worker resume and decision lifecycle; and journal observation, encoding, append and total. Journal append includes existing compression/hash/readback work. Nested measurements are inclusive and must not be summed as disjoint time. Update total excludes its trailing bounded timing-summary emission, measured separately as `performance_emit`. These are elapsed wall times, including preemption or waits, not CPU utilization or GPU work measurements.

Every new ordinary journal event retains its UTC timestamp and sequence while adding an event-entry monotonic anchor with explicit available/unavailable status. The anchor precedes observation, encoding and append. Missing, throwing, invalid or backward clocks remain explicit and must not fail gameplay or logging. Monotonic values are comparable within a process/session, not across restarts. Existing archive hashes, append verification, segment/storage/event limits, action-to-callback linkage and retry protections remain.

The collector retains at most one pending and one current window. It rotates before writing the pending summary, preserving measurements added by that write for a later window. A failed real journal append retains the unacknowledged bounded window; the journal error gate blocks further timing writes or retries. The opt-in predicate depends only on the explicit recording setting, so an I/O error does not silently erase retained measurements. Explicitly disabling recording clears in-memory diagnostic state. Invalid clocks omit affected unknown samples/receipts, with clock-failure accounting where a later summary exists. A crash, shutdown, logging failure or disabled recording can leave an unflushed tail; absence of a summary is not zero cost. This is bounded diagnostic coverage, not a complete event ledger.

Decision receipts distinguish elapsed time from summed active coroutine-resume wall time, with resume count and maximum resume duration. Only a completed result supplies its existing evaluation count; partial/cancelled/error counts remain unknown. Current advice receives a receipt only when the actual result object and current public-state/game binding agree. Root's independent review found no blocking runtime/journal behavior regression. It documents one limit: synchronous decision/presentation exceptions propagate as before and bypass an error timing receipt; coroutine errors are recorded explicitly. No additional protected-call boundary wraps a yieldable decision. Original callback behavior, snapshot privacy, deterministic policy inputs, action/resource guards, computation ceilings, native CPU settings and animation speed remain unchanged.
