# V02 learning review and next bounded stages

Date: 2026-09-16. Read-only analysis of frozen T02/V02 code, manifests, summaries and JSONL records. Only existing JSON data were parsed/aggregated. No checkpoints were executed, simulator episodes run, source workers launched, or code changed. No new research browsing was needed.

**Conclusion:** T02 implemented the intended distinct-missing-sticker proxy, but obtained no positive terminal examples. Its evaluated policy is worse than the prototype heuristic on observed blind progress and exhibits uniform opening liquidation and repeated-swap failures. The strongest next step is a lossless current-advisor teacher bridge plus targeted source validation, followed by supervised learning and critic calibration. There is no evidence that a larger network, lower-bit precision, or more of the same PPO run would solve the current failure.

## Correct objective, insufficient useful return signal

Frozen [objective.py](C:/Users/trevo/Documents/GitHub/Brainstorm-Rerolled-Rerolled/tools/advisor_eval/development355/jobs/T02/frozen/tools/advisor_learning/objective.py) uses the 91-missing public mask, distinct held identities and a qualifying simulator terminal condition. It pays no acquisition/holding reward and no bonus for a zero-new-sticker win. `gamma=1` and shaping `0.05 * delta(blinds_cleared)`, reset to zero potential at a true terminal, preserve the unshaped return over completed episodes. Every observed complete T02 loss therefore has total undiscounted shaped return zero. Short-horizon progress rewards do exist, but they cancel at failure.

That design avoids rewarding the wrong achievement; it cannot supply successful-return evidence that was never collected. A value model trained only on losses can learn low returns, and policy updates can still change behavior through approximate bootstrapping, finite rollout horizons, entropy and imitation. A declining value loss or 499 updates does not mean it learned which early purchase, retained anchor, discard, or consumable earns stickers later. The logs do not isolate which of those terms caused opening liquidation, so treat it as a measured failure and a learning-signal hypothesis, not a proven causal diagnosis.

Frozen [train.py](C:/Users/trevo/Documents/GitHub/Brainstorm-Rerolled-Rerolled/tools/advisor_eval/development355/jobs/T02/frozen/tools/advisor_learning/train.py:383) gives T02 imitation weight 0.1 only on qualifying **play** recommendations from the prototype heuristic. The teacher is explicitly not the existing advisor. Shop choices, opening anchor retention, rearrangement, consumables and long-run strategy receive no such teacher supervision. The [GAE implementation](C:/Users/trevo/Documents/GitHub/Brainstorm-Rerolled-Rerolled/tools/advisor_eval/development355/jobs/T02/frozen/tools/advisor_learning/gae.py) excludes invalid transitions and bootstraps the preceding valid transition from the observed pre-boundary value; it does not fabricate unresolved terminal losses. Preserve that distinction, while monitoring how little supported long-horizon data reaches the critic.

## Recommended next stages and exit criteria

These are proposed stages, not jobs started by this review. Existing source-worker budget remains zero and expiry censors stay enabled. Each future execution needs its own bounded registration; this report does not extend T02/V02 budgets.

**1. Build the advisor teacher dataset before another RL run.** Use only authorized public journal snapshots with current fingerprint-matched recommendations, and label each record with advisor version, complete public target mask, opening/run/seed family, phase and action. Map its exact action losslessly into the learner representation. Cover opening retention, discards, shop acquisition/retirement, Perkeo consumable management, copying/rearrangement, pack decisions and ordinary plays. Separate recommendation, user behavior and verified outcome; do not infer one from another. The journal omits full candidate distributions, so initial policy targets are hard recommendations, not invented soft search probabilities. Exit with a frozen dataset manifest, coverage/mapping counts by phase, grouped run/seed splits and no hidden-information access. Missing or unrepresentable labels should be reported, not coerced.

**2. Supervised distillation with the current model as a control.** Train advisor action imitation across supported phases on GPU BF16, and evaluate exact/mapped action agreement by phase on held-out runs. Weight phases so numerous hand decisions do not erase rare shop/retention lessons. Retain the existing 5.6M-parameter architecture first to isolate the data change. Record opening decisions, unnecessary anchor sales and repeated identical public-state/action cycles as diagnostics. Do not add an arbitrary per-step penalty or hide legal sales/swaps merely to make evaluation look better. A later explicit history feature or recurrent core is justified if repeated-state failures persist after the relevant teacher examples are representable and learned. Exit with improved held-out supervision metrics and no uniform opening liquidation/rearrangement-cycle behavior on fixed public-state probes; this still does not prove win-rate improvement.

**3. Validate terminal mechanics and obtain trustworthy successful examples.** Execute the future bounded fixture plan in [PERISHABLE_EXPIRY_REFINEMENT.md](C:/Users/trevo/Documents/GitHub/Brainstorm-Rerolled-Rerolled/tools/advisor_eval/development355/PERISHABLE_EXPIRY_REFINEMENT.md) only under a separately registered source budget: Burnt copy/event order, Perkeo mutation/RNG order, expiry/passives/rental/Negative effects, downstream consumable and whole-row interactions, and original Gold callback ownership/eligibility. Use the existing source-grounded advisor to produce successful supported trajectories when possible, retaining failures and scope limitations as well. Controlled near-terminal practice states may teach award/value mechanics, but must be labeled synthetic and excluded from natural-opening success metrics. Repeated favorable-seed training is curriculum, not held-out evidence. Exit with verified source-scope success receipts and a usable positive/negative terminal dataset; if no successful supported examples exist, do not claim the sticker-return critic is trained.

**4. Fit/calibrate value, then cautiously fine-tune.** First predict distinct terminal new-sticker count from validated observed outcomes, with separate diagnostics for win probability and short-horizon blind survival. Unknown/censored outcomes remain unlabeled. Sample sufficient successful sequences to make their signal visible, while retaining/calibrating against the actual evaluation distribution rather than mistaking a balanced training set for prevalence. Then collect fresh on-policy experience with the cloned policy, warm up the critic, and add bounded PPO updates while retaining a supervised teacher anchor/control. Monitor actual terminal new-sticker count, phase action regressions, cycle rate, unsupported coverage and calibration. Compare against the existing advisor and prototype heuristic on the same qualified opening distribution before calling the learner better.

**5. Add planning or capacity only for a measured residual problem.** Once transitions and leaf values are trustworthy, use bounded public-information search at a few difficult shop/discard/consumable decisions and distill improved choices. Reanalyse a bounded set of disagreements. Increase model size only if the current model demonstrably underfits adequate supervision or larger capacity improves held-out return per elapsed time. More VRAM use alone is not a success criterion.

## How the modern research informs this order

These are engineering applications of primary research, not claims that those papers solve Balatro:

* **Staged imitation then fresh online calibration:** [WSRL (ICLR 2025)](https://arxiv.org/html/2412.07762v1) supports collecting fresh pretrained-policy experience before aggressive online updates. Its experiments use continuous-control/off-policy methods, so this is motivation for the distribution-shift precaution, not a guaranteed PPO recipe. The [official TorchRL PPO tutorial](https://docs.pytorch.org/rl/main/tutorials/coding_ppo.html) supports refreshing on-policy rollout batches rather than mixing arbitrary old demonstrations into the PPO objective.
* **Successful sequences and stable targets matter:** [DreamerV3 (Nature 2025)](https://www.nature.com/articles/s41586-025-08744-2) motivates robust input/return scaling and recurrent state, but a world model cannot create reliable positive reward evidence from an incorrect simulator. [Dreamer 4 (2025)](https://arxiv.org/html/2509.24527v1) separates useful successful imitation sequences from broad dynamics data; borrowing that distinction is more relevant here than reproducing its large video-model training stack.
* **Search as a later supervision source:** [EfficientZero V2 (2024)](https://arxiv.org/html/2403.00564v2) motivates improved policy/value targets and bounded reanalysis. Its benefits depend on useful models and targets. Here the first model to qualify is the rules engine, and search must sample hidden futures from public information rather than inspect the true seed.

The immediate deliverable should be a trusted teacher/action bridge and a validated route to positive terminal examples. This directly addresses the failures found in V02; another same-data capacity or precision sweep would not.
