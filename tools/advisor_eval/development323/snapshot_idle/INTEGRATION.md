# Snapshot HUD key stability — detached candidate

The current snapshot copies every `current_round` field, including the display-only `current_hand` aggregate. `fingerprint` then serializes that aggregate. A HUD update can therefore change the advisor's state key even when actual hand levels, cards, cash and round resources are unchanged. The existing runtime refresh loop treats a changed key as a new decision. This identifies a mechanical unnecessary-invalidation path; no observation establishes how often it occurred in the user's run or its CPU cost.

Preserved `runs/planet_pool_source1/source/functions/common_events.lua`, SHA256 `522ea0810101de1004685e13e7ed05a750b4e115e5231dca2cbc97aeb8c3e5fc`, defines complete `update_hand_text` beginning at495, before `eval_card`. It writes `G.GAME.current_round.current_hand.chips`, `.mult`, `.handname`, `.chip_total` and `.hand_level` while updating/pulsing the HUD objects; actual scoring resources are not stored by this function. No production Brainstorm consumer reads `current_hand`. The preserved source was read only; no callback or executable was invoked.

The candidate copies the round table and removes only `current_hand` from that detached copy. Every other field stays captured, including unknown fields outside that HUD aggregate. Actual hand levels live in `snapshot.hands`, accumulated blind chips in `snapshot.chips`, and hands/discards in the captured round fields. The live game-shaped input is unchanged. This intentionally changes deterministic observation/sample keys to exclude HUD state; earlier saved traces, captured snapshots and frozen policies remain untouched.

New manufactured tests capture metadata only, without loading a scorer or Decision. Repeated captures including full Gold status and qualified Perkeo source proof are stable; mutating returned outputs cannot alter future captures. Known render transforms, hover state and stripped Blueprint tooltip caches leave the key unchanged. All five HUD values may change without invalidation, while actual hand level, accumulated chips, current-round resources, cash, physical card/rank/order, consumable ability and Gold history continue to change it. The existing snapshot/Gold/Perkeo suites remain part of routine focused validation.

Gold capture and Perkeo capture themselves return fresh detached data and maintain no shared mutable result cache. `by_key` and `targets` alias the same newly created Gold rows within one output, but later captures rebuild them. Snapshot's use of global `G.P_CENTERS` for Planet source qualification is an unrelated existing API coupling; normal runtime passes current `G`, and this candidate does not alter it.

Stage only `snapshot.lua`→`Brainstorm/Advisor/snapshot.lua` and `test_advisor_snapshot_idle.lua`→`tests/advisor_snapshot_idle.lua` after review. `stage.py` verifies source and current base hashes and backs up current work before mutation. It has not run during candidate authoring. No installation, source experiment, captured replay, game control, save/profile read, seed search or full attempt is performed by this package.
