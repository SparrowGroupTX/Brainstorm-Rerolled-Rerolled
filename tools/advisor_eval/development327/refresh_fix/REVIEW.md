# Runtime scheduling and nondecision capture review

Read-only inspection of the root's frozen selected public observations found a concrete scheduling integration defect. No player save, original-source experiment, captured-state policy run, game control or new external log capture was performed for this component.

The exact observations remain in `../captured_logs/`; their compact lookup is `../events_index.json`, with audit provenance in `../audit.json`. Event 3319 (also repeated in 3320) records completed decision 1492, Ante 5, phase `pack`, action `choose`, 48,449 evaluations and exactly one resume. Its active and maximum-resume durations are both 1.845295300000089 seconds. It began at monotonic 1281.7723687 and finished at 1283.6176793. The preceding action opened a Jumbo Celestial Pack. The emitted timing window is event 3318. This is a pack decision, not a shop decision merely because the preceding action occurred in a shop.

The previous runtime created workers only for hand and shop decisions. Pack and blind decisions called the same decision entry with a nil yield callback directly in `refresh`. Consequently the existing shop-scoring yields were ineffective during a pack comparison. Blind routing had another integration gap: it supported `options.yield_fn` every 64 scores, but the decision entry never forwarded its worker callback.

The runtime now also creates detached workers for pack and blind phases. The decision entry copies blind-routing options, supplies the worker callback as the default and retains an explicit caller callback. Scheduling changes neither candidate order, completed results nor score allowances. A short decision may still complete during its first resume. The four-millisecond update allowance is cooperative, not a hard bound on every individual operation.

Separately, a ready game state outside a decision phase previously built a complete snapshot, then invalidated the nil key; the next frame repeated the capture because no key existed. A shared pure `snapshot.phase` classifier now lets runtime refresh perform the same invalidation without that full copy. It does not change `snapshot.capture` output in other phases. The product's separate observation path still captures fresh state when a ready unsupported endpoint must acknowledge an earlier action; logging and both execution recapture checks remain intact.

The selected window's 134,608 snapshot captures and 31,100 fingerprints are consistent with redundant capture work, but their difference is not a measured count of this specific path. The window has 90.40186490000792 cumulative seconds inside fingerprinting. Every-worker-slice full comparison remains in place to reject stale work. The logs also show a shop decision with a 0.5544971000001624-second maximum resume, so these changes do not explain or remove all long operations. Timings are inclusive elapsed durations; nested measurements cannot be added as independent CPU usage.

Manufactured fixtures verify complete yielded-versus-synchronous pack and blind results/diagnostics, exact evaluation totals, unchanged inputs and caller options, bounded route yields, and the existing cap. Runtime fixtures verify no partial publication, no synchronous work from panel refresh, same-worker drag waits, cancellation on changed cash, stale action rejection, hand-to-other-to-hand cancellation and immediate fresh work, drag ending in another phase, and zero complete runtime snapshots during 120 nondecision frames plus explicit refresh calls. A direct other-phase capture retains all public card information. Existing product and journal fixtures pass.

Validation: 10 Lua fixtures, 1,892 checks, all pass. This is manufactured regression evidence, not a rescore of the observed pack, a new complete attempt, measured post-install speedup or a win-rate change. All historical experiment authorities remain closed.
