# Public observation archive review — release 327 development evidence

This directory contains a read-only review and bounded transformations of the parent's eight frozen public-log copies. No executable, source mechanic, policy, search, scoring, save, profile or live gameplay was executed. The existing captured originals were not changed or deleted. The BRJ3 proposal below is **development only and is not shipped**; the selected runtime release keeps BRJ2.

The existing BRJ2 archive already compresses each frame and exactly references the latest complete public snapshot within a segment. It retains an event checksum, frame checksum, predecessor chain, compression roundtrip check, verified append length and exact readback. Segment boundaries reset snapshot references. Neither semantic snapshot equality nor an advisor fingerprint substitutes for original event bytes.

The initial frozen-copy analysis counted 1,831 events and 303,399,440 decoded bytes. There were 951 large strings across `details.fingerprint`, `details.before` and `details.after`, totaling 173,541,923 encoded JSON bytes. A two-entry dictionary found 631 exact cross-field repeats accounting for 115,164,631 bytes, leaving 320 definitions. The source contains 319 unique strings. This count measures repeated definitions, not compressed storage or CPU cost; `reuse_metrics.json` records its 3.672-second bounded pass.

A detached BRJ3 candidate keeps one snapshot slot and two fingerprint-string slots. At most nine exact parts reconstruct the original event; all original-event, frame, compression, append, sequence and segment checks remain. It performs one compression per event and does not use lossy semantic equivalence. The decoder retains the old BRJ2 and JSONL paths. Twenty-three focused manufactured tests passed, including Unicode, three-value eviction, cross-field reuse, old-format compatibility, reference reset, missing reference, bad slot/type/hash and unchanged event bytes.

The first captured roundtrip harness failed before processing the first event because its Lua long-string table-key literal lacked separating spaces. This was a harness parse error, not a codec failure. Its exact script, failed receipt and empty partial output remain as `roundtrip_captured_failed1.py`, `captured_roundtrip.json` and `roundtrip_outputs/`. The corrected pass was separately recorded in `captured_roundtrip2.json` and `roundtrip_outputs2/`; it finished in 30.328 seconds under a 45-second cap. All 1,831 original event hashes matched after encoding and decoding. Stored size changed from 16,074,649 to 8,850,223 bytes, a 44.94% reduction for these fixed copies. This establishes an offline lossless codec result, not live frame-time or gameplay improvement.

The parallel runtime review then found that raw internal fingerprint strings bypassed the separate public-snapshot redaction and included internal state. The selected repair exports opaque identity records at the product logging boundary, retaining the exact full strings internally for freshness and action validation. Because future exported fields are small objects, the fingerprint dictionary no longer has material prospective value. The BRJ3 candidate is retained as development evidence rather than adding an unnecessary runtime format migration.

The separately planned prospective calculation uses the selected identity schema: `schema=1`, `kind=snapshot_fingerprint_sha256`, `status=available`, exact original string `byte_length` and lowercase SHA-256. It transforms only the three declared top-level identity fields on `auto_run` events and the known interrupted-action fingerprint path. Missing hash behavior belongs to the runtime fixtures; this size sample uses available SHA-256. All other decoded event values are compared after transformation. It uses the existing BRJ2 Lua writer and compressor, without running the product controller or game.

`prospective_export_plan.json` was written before that separate pass. `prospective_export_size.json` records 1,831 events, 951 transformed fields, 32.515 seconds and no errors. Stored bytes changed from 16,074,649 to 5,085,667 (68.36% smaller); decoded bytes changed from 303,399,440 to 130,016,334 (57.15% smaller). The derived sample is in `prospective_export_outputs/`. This deliberately replaces internal serialized identities with opaque records and is **not a lossless replacement for historical logs**. The original observations remain preserved, and the result does not establish a live CPU reduction or win-rate effect.

Each captured-data pass was bounded at eight files, 64 MiB stored input, 512 MiB decoded input, 12,000 events and 45 seconds. Failed and successful receipts are separate. These are logging inspections/codec validation, not additional source or complete-attempt experiment leases. No old experimental authority was renewed.

For context efficiency, the selected solution is the parent's separate bounded inspector and exact record locators. A compact report must retain references to the full originals; a summary is never presented as a lossless replacement. Raw historical fingerprint strings should not be dumped into the model context.
