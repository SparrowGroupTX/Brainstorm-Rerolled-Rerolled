# Bounded offline timing analysis

Proposed mappings: `analyze_player_timing.py` to `tools/advisor_eval/analyze_player_timing.py`, and `test_advisor_player_timing.py` to `tests/test_advisor_player_timing.py`. Both targets must be absent. `stage.py` checks the manifest, candidate bytes, decoder dependency and every target before its explicit `--stage` operation. No runtime policy or existing tool/test is changed by this package.

Usage after staging: `python tools/advisor_eval/analyze_player_timing.py explicit-file.jsonl another-file.brj --output new-report.json`. Inputs are literal files; there is no directory scan, glob, game/profile access or input modification. Output creation is exclusive. Defaults are 16 files, 32 MiB per file, 64 MiB total stored input, 128 MiB decoded records, 50,000 events, 100,000 decision receipts and 20 retained examples. Every command-line override is bounded by a hard ceiling in `HARD`. Original event/frame decompression limits and hash checks come from the existing `read_player_log.py`. Per-record numeric timings must be finite, nonnegative and at most 1e12 seconds. This prevents nonfinite aggregate arithmetic while exceeding any realistic process lifetime.

Each metric is aggregated independently with its summed count/total, largest sample and complete histogram. Mean is total divided by count. P50/P95/P99 are integer-rank histogram bucket bounds, never exact percentiles; overflow has no finite upper bound. Update phases, draw phases, nested journal/snapshot/decision costs and broad frame intervals remain separate. No nested sum or CPU percentage is invented. `update_total` excludes `performance_emit`; the outside-update portion of a frame gap cannot identify animation, GPU waits or CPU work.

Decision receipts report wall/active/resume totals and maximum active chunk separately. Only explicitly completed decisions with a present evaluation count contribute known score-call totals. Completed decisions missing that value remain unknown. Cancelled/error receipts do not receive imputed score counts. Dropped source receipts/examples and the analyzer's own bounded example omissions are distinct.

Clock comparisons and duplicate window/decision detection use the validated BRJ2 session identifier. Explicit decoded JSONL files have separate file scopes because decoding has removed archive session metadata. No cross-file clock subtraction or global window-ID deduplication occurs for JSONL. Within a scope, duplicate/gapped event sequence, duplicate/overlapping windows, duplicate decision receipts, invalid records, corrupt archives or a cap stop produce an incomplete report containing the valid prefix. No partial window contributes metrics. Source files must remain unchanged during reading.

The tail is always explicitly uncertain: the last summary's own logging cost and later work may not have reached another compact window. Extra events after the last window and any same-scope event-to-window clock gap are reported without imputing missing work. Old UTC-only events cannot provide new precision. This analyzer summarizes supplied observations; it does not prove a complete session, freeze cause, CPU utilization or system speedup.

Validation: 23 manufactured Python tests passed, including compressed/raw archive decoding, exact session scopes, weighted histogram aggregation, unknown score counts, byte/event/file caps, corrupt tails, duplicate/overlapping data, malformed clock/drop counts and exclusive output. All inputs were generated in the tests' temporary directories. No player/public log, save, profile, source executable, captured replay, search or experiment was read or run.
