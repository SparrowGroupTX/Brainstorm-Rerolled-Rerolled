# Bounded Burnt fallback, layered on304 startup fixes and adaptive quota

This draft contains four runtime files: `Advisor/collection_search.lua`, `Core/collection_search_product.lua`, `Core/auto_run_product.lua`, and `UI/collection_run.lua`. It includes the separately reviewed adaptive quota and preserves304's persistent-loading-cache/main-menu fixes and all corresponding tests. No native DLL change or new native/source experiment was made.

One explicit user request owns at most two sequential worker generations. The strict phase requires the original Yorick/Perkeo Charm opening, copy by Ante5, and Burnt by Ante5. It receives at most9 seconds (one third of smaller requests). Only an owned, matching, fully exited `not_found` or `timeout` result can admit the optional second phase. That phase removes only Burnt's fixed timing requirement and receives at most the remaining18 seconds, further reduced by the remainder of the original27-second search wall envelope. Allocated native caps sum to at most27 seconds; the enclosing product/controller retains the original30-second limit. No budget or seed cursor resets between phases.

The product checks the fresh profile, missing population, input token, run identity, original deadline and actual worker exit before relaxing. Stop, foreign/malformed receipts, errors, unavailable/backward clocks, or changed context prevent fallback. A late result is checked again after polling. Each stage's actual request/result, generation, start cursor and cap remain in the successful receipt; the failed first phase is retained separately. A partially dispatched second worker must drain before ownership can end.

The second request keeps the missing quota and actual missing identities, no-Perishable rule, copy alternatives, deck/stake and Ante window. A still-missing Burnt can therefore remain a quota candidate by the later deadline. Successful relaxed launch metadata uses the actual three-target explicit normal-opening recipe and marks Burnt relaxed; it never claims Burnt was mandatory or acquired. The genuine opening still requires the first Small Blind Charm Tag and two Souls. This change does not create a pack automatically or skip any extra blinds.

The page defaults new explicit starts to `Burnt: flexible`; the toggle preserves an explicit required-Burnt preference. Direct/manual query callers continue to default to strict single-phase behavior unless fallback is explicitly enabled. The automatic facade defaults to the newly authorized flexible behavior while preserving explicit false. Both automatic and manual status paths identify when Burnt is relaxed.

The page retains the most recent explicit request owner. Immediate manual and automatic Start rejections take priority over stale facade status, persist through redraw and force a redraw when the rejected click leaves the overlay open. Two bounded live text rows then follow that owner's waiting, search-stage, successful-start or stop status. A successful original manual launch retires its completed owner before advisor settings invalidation, so the ordinary stop hook cannot relabel the completed start as cancelled. Pending manual owners still cancel normally.
