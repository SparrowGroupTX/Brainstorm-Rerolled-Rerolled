# Auto-run interaction and Resume — release 325

Ordinary input no longer revokes an explicitly started auto-run session. Keyboard/mouse actions, menus, card dragging, settings edits and checkpoint saving retain the session while fresh-state and execution checks continue to protect every action. Benign input waits end automatically when controls settle. Hard time/action limits, invalid profile or run context, missing evidence and execution/logging errors still halt; removing input cancellation does not remove these guards.

Explicit Stop pauses the existing in-memory session. Resume keeps the selected configuration, session identity, consumed run/action counts, original run/session clock anchors, pending-action acknowledgment and terminal monitor. Progress watchdogs exclude the pause/input wait without extending hard session/run limits. Resume closes its overlay and waits for a fresh eligible state before dispatching anything. It neither calls Start nor resets the current run. A found seed receipt and an already-started run remain associated with their original request so they are not searched or launched twice. Session consent is not persisted across a normal game restart.

Stopping an active search requests cancellation once and drains the existing worker. After it has exited, a later explicit Resume authorizes a new product search capped at 30 seconds, with a distinct request ID and the same session, cursor and recipe. Its old allocation remains spent. This supersedes earlier development wording about reusing only the old remaining search budget. A completed found receipt can resume without a replacement search. No product Resume supplies authority for tool-driven search, source components, simulations or complete attempts.

The HUD has dedicated Stop and Resume actions. A stopped resumable session continues to show Resume; a pending resumption shows Stop. The collection page places Resume beside Stop and Full status on the existing row, while Start remains a clearly separate new-run request. Buttons honor their last drawn role and cannot fall through to Execute. Generic input and settings changes cannot cancel an auto-owned shared search. Ctrl+A and fast reroll cannot start an overlapping request or replace the owned run. Independent manually started search retains its existing input cancellation behavior.

Checkpoint operations remain user-keyed. The existing settled-state, fresh serialization, byte/identity verification, error reporting and persistent retry protections are unchanged. A save or raw load request does not adopt a continuation. Only successful verified load completion, after advisor invalidation, allows the product to wait for fresh advice and adopt the restored state within the same session. The controller logs a manual checkpoint continuation and any interrupted pending action as unresolved. It retains consumed work and original limits, and binds fresh terminal evidence; restored `won` fields do not establish a win. A checkpoint adopted while stopped still requires explicit Resume.
