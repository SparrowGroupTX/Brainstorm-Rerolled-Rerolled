# Detached frame timing hooks

The candidate adds optional `Brainstorm.Advisor.performance` calls to the existing Core update wrapper and UI draw wrapper. No policy, sampling, score cap, callback ordering, game action, original argument, return or error handling changes are introduced. The collector methods must implement the parent's fail-open API. This package does not catch errors thrown by game or product callbacks.

Core chains `game_update`, `checkpoint_update`, `search_update`, `journal_update`, `advisor_update`, `auto_update` and `legacy_reroll` spans in their existing sequential order. `advisor_update` includes the adjacent released-hotkey bookkeeping; `journal_update` includes journal hook installation and settled post-action update. The legacy reroll span includes its attention-text branch and can contain a synchronous native call in normal product use; no such call occurs in these fixtures. `game_update` is the previously installed update function, including any earlier wrapper, not a claim to isolate vanilla game code. Synchronous journal events invoked by other callbacks remain within their corresponding span, so `journal_update` is not all logging time.

`update_total` is inclusive of these top-level spans and scalar flag construction. Nested advisor refresh, worker and snapshot durations must not be added to it again. The total ends before `P:flush`; the collector records its bounded sink cost separately as `performance_emit` for a later window. Draw records `original_draw`, `advisor_hud_draw` and inclusive `draw_total`, with no flush or journal write. CPU-side draw call duration does not measure GPU completion, presentation or vsync.

The update wrapper forwards `dt` unchanged. It is recorded as `update_argument_dt`, separate from the wall-clock frame-start interval and the selected `G.SETTINGS.GAMESPEED` scalar. The prior UI speed feature sets that scalar but does not transform this wrapper's argument. The inter-start interval includes prior update, draw, presentation, wait and scheduler time; it cannot attribute a pause to any one component by itself.

Flags are constructed only after an enabled `begin_frame` returns a timestamp: finite numeric state, stage, ante, round and game_speed; boolean paused, dragging and advisor_worker; and auto_active only when the already-returned AutoRun update status has a boolean active field. No new snapshot, status callback, Gold scan, identity copy or gameplay mutation is performed. Unknown/nonfinite scalar fields are omitted. The existing AutoRun API already returns a status copy during its normal update; the hook only reads that existing return.

If the collector is absent, callbacks execute unchanged. When logging is disabled, the collector returns nil at frame/draw entry, so there are no finish calls, flag construction or flush. A failed-open finish stops the chained component clock sequence rather than inventing later intervals; the collector still owns end-frame/flush validation. An original update/draw or product callback error propagates unchanged, so an incomplete frame is not falsely completed or emitted by the wrapper. The collector is responsible for bounded memory, timing validation, recording abandoned spans where appropriate, and safe emission.

`test_advisor_frame_timing.lua` executes only the actual extracted Core wrapper and full UI module under manufactured callbacks/clock values. The fixture checks 76 conditions, including exact order/self/arguments/nil-vararg arity, the existing ignored returns, known scalar timing attribution, emission exclusion, disabled/absent behavior, invalid fields, failed timing chains and original error-object propagation. The existing Core and UI fixtures add 142 checks. These are ordinary regression fixtures, not original-source components, search, captured replay, complete attempts or live CPU measurements.

`stage.py` validates all candidate and current-base hashes before copying, and preserves existing bytes in a timestamped package backup. It is not run during candidate authoring. Only reviewed Core/UI candidates and the new manufactured fixture are stage targets. Installation and exact-installed validation belong to root. Current running game, saves, profiles, settings and DLLs remain untouched; all historical experiment authority stays closed.
