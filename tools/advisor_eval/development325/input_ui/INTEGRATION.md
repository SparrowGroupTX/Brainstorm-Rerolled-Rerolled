# Detached ordinary-input and Resume controls

Five candidate files implement the agreed input/UI portion of root's session lifecycle. Root owns `auto_run.lua` and `auto_run_product.lua`: `manual(reason,kind)` is a non-stopping notification, `stop(reason)` explicitly pauses an existing session, `resume()` takes no options, `engaged()` is a cheap predicate including arming/active/stopped-resumable/draining ownership, and `owned()` keeps its internal-callback meaning. The read-only `status_report()` must expose `resume_available` and `resume_pending` booleans.

Ordinary keyboard/mouse notifications still run before their original handlers. Generic shared-search cancellation is skipped while an auto session is engaged. Ctrl+A cannot cancel that session's native search, toggle its legacy search or start a second request. Standalone manual searches retain their existing input cancellation. The new-search page refuses a manual search while an existing auto session owns the run. Configuration controls persist the next-start recipe without stopping or replacing the already-copied session request.

Auto HUD Stop calls `stop`, never the ordinary-input method. HUD Resume calls only `resume`, with no new options or fallback to Start/Execute, and remains visible while the product reports a resumable session. The existing drawn-button latch continues to govern clicks; a stale manual-search Stop cannot cancel a newly owned auto receipt. A resumed-but-settling session shows Stop. Page Resume occupies the existing Stop/Full status row; Start remains explicitly a new searched run. Page Stop captures ownership before calling the controller, then avoids any second shared-search cancellation when auto owned the request. The controller owns cancellation/draining and retention of a found receipt.

Checkpoint save/load retain settled-state checks, fresh serialization, verified bytes/identity, failure receipts, duplicate-key protection and retry counts. They keep non-stopping request notifications but no longer directly stop auto-run or its owned search. Only a successfully verified restored state sends `manual('Checkpoint loaded.','checkpoint_loaded')`, after the existing advisor settings invalidation. Root uses that completion notification for continuation adoption. The runtime candidate changes only the shared-search stop guard inside `settings_changed`; all existing token, retry-generation and worker invalidation remains.

The new actual-hook manufactured fixture has 86 checks. Existing Core/status/startup/layout/checkpoint fixtures add 490 checks, for 576 focused checks in six isolated Lua states. Geometry checks have no bound violations, with Resume on the existing row. Existing runtime's HUD Stop stub must be updated by root from a stopping `manual` stub to a dedicated `stop` stub. No fixtures execute native/source search, source gameplay, a real checkpoint, player files or a complete attempt.

The first fixture failed because its helper lookup assumed LF while a repository fixture used CRLF. `failed_fixture1/` preserves the exact failed fixture and cause; the test normalized line endings and passed. This is a manufactured harness failure, not a product/game result or consumed experiment lease.

`manifest.json` binds original bases, candidates, fixtures, relevant dependencies and focused output. `stage.py` must check every current base before any writes and preserve old bytes in its timestamped backup. It has not been run during authoring. Root's separate changes to runtime lifecycle may make the runtime base differ; then a reviewed narrow merge is required rather than overwriting its new work. No native/search module was changed by this package. All historical experiments remain closed; installation and final exact-byte validation belong to root.
