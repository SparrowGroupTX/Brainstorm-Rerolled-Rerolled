# Collector and runtime integration review

Read-only comparison covered `Advisor/performance.lua`, current `Advisor/runtime.lua` and `Advisor/player_journal.lua`, with runtime/journal baselines from the frozen repository `runs/idle323_installed/policy`. No player file, executable/source callback, source experiment, captured replay or live measurement was accessed. The exact reviewed hashes belong to `collector_review.json`.

No blocking issue was found in the reviewed implementation. The collector is opt-in through existing player logging, uses a finite monotonic wall clock and never falls back to CPU time. Missing, throwing, nonfinite and backwards clocks suppress invalid intervals. Disabled collection makes no injected clock call and clears retained windows; outstanding decision tokens cannot cross that consent generation. The collector stores one pending and one current window, a fixed label map with eleven histogram buckets, at most eight slow frames and thirty-two decision receipts, with explicit truncation counts.

The first due emission rotates the window before calling the journal, so its own observation/encode/append duration belongs to the following window. The exact pending object survives a false return or exception and is acknowledged only after accepted writing. New measurements continue into the separately bounded current window. Reentrant flush is suppressed, and at most one attempt occurs per five seconds. The journal's compact timing event supplies empty observation context, retaining existing encode/append/archive/sequence protections without another full snapshot.

Runtime timing wraps existing capture/fingerprint/refresh/presentation calls without changing their outputs or adding error-catching boundaries. Coroutine work remains protected only by its original `coroutine.resume`; each resume is timed externally, so yields remain legal. Both synchronous strategy work and coroutine completion can produce a receipt. Invalidated workers are cancelled and coroutine errors retain their existing unavailable-state handling; cancelled/error receipts receive no evaluation/action credit. An unhandled synchronous gameplay error still propagates and can leave no completed timing receipt. That is an incomplete measurement, not a recorded successful or failed game outcome.

Aggregate `decision.resume` measures actual timed calls, including a worker whose decision token was absent because logging began mid-worker. It may overlap a completed receipt's `active_seconds`; it must never be added to that receipt or its parent update total. A nil, stale or already finished token receives no owned resume count or new receipt. Decision elapsed duration includes waits/drag pauses; active duration includes each resume, including any presentation completed inside that resume. Same-key result reuse creates no new decision. Journal advice timing is included only when the snapshot is current and the receipt's result identity equals the published result.

Instrumentation itself has a cost and can change how many yields fit into one frame's existing elapsed-time slice; it does not change score caps or deterministic state keys. Update/draw/decision spans are elapsed wall time, not CPU utilization, GPU completion or evidence of stronger play. A clock fault or journal failure can make timing incomplete. Retained tail records and histograms provide bounded diagnostics, not every raw frame or an exact percentile distribution.

The detached collector fixture checks 181 manufactured conditions: disabled/invalid clocks, fixed histogram allocation and boundaries, raw duration aggregates, active-versus-elapsed decisions, duplicate/generation/incomplete rejection, aggregate-versus-owned resume semantics, 8/32 retention caps, largest slow-frame retention, scalar flag restrictions, five-second gating, rotation before sink timing, reentrant suppression, failed writes with exact pending retries, current-window preservation and acknowledgment. Prior frame-hook fixtures separately cover 218 conditions. Root owns runtime's enabled timing fixture and final full validation.
