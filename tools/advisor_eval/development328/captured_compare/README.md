# Fresh captured-public comparisons — preparation only

This package has not registered, reserved or run any captured-state job. Five
manufactured/inert harness tests pass. They compile the serializer/driver and
derive both exact frozen runtime initialization prefixes without running a real
policy on any captured state. No source initialization, save/profile read,
selected-action rescore, search or game control occurs.

Root can load each `prepared/P0N_registration_inputs.json` and call its own
`validation_cycle.register(spec['job'],spec['files'],spec['command'],spec['metadata'],spec['external'])`.
Registration and execution are separate root operations. Only the freshly
authorized P01–P06 slots are accepted. `validation_cycle.run` supplies the shared
30-second process watchdog and original one-use spent receipt. The worker also
checks the parent reservation/authority, every registered file/runtime hash and
each complete94-file policy manifest, then creates `comparison_started.json`
exclusively before evaluating either role. Copying the draft cannot execute it.

The prepared states are P01 sequence2722, P02 sequence3282 and P03 sequence3829.
Inputs are byte-identical redacted public snapshot files referenced by the
preserved trace. Baseline is `log327_installed/policy`; candidate is
`shop329_installed/policy`. The latter digest is
`0012f84ff812038cf2f2e1b82220877314897b33188b4d9ca6cd6b0a0a87f64c`.
The command contains the exact current Python and `{job}/compare_public.py`.
The two permitted external dependencies are that Python executable and the
isolated `lua51.dll`; no Balatro executable is opened or launched by this worker.

Each role derives its dependency graph from its own frozen `runtime.lua` prefix
before `A.defaults`. Only the filesystem loader, execution module, retry modules/
generation line and two live opening integrations are replaced or omitted.
The unchanged C08 wiring verifier checks49 declared modules and40 edges with
inert tests; Gold module presence does not enable or alter the supplied public
objective. Every production decision module is preloaded from its own freeze;
filesystem/native loaders, RNG and dynamic loaders are unavailable at decision
time. There is one full `decision.run` per role with product defaults and no
action dispatch. Exact input fingerprint equality is checked privately and never
exports the internal text. The input file SHA256 is checked before and after.

Hand decisions retain140000 actual score calls, shop/pack50000; the role caps and
aggregate are explicit in registration metadata. No blind-phase cap is inferred.
The same30 seconds covers startup, hashing, both isolated states, serialization
and output under the root watchdog. Lua score/instruction deadline checks are a
secondary guard, not a substitute for the outer process limit.

`baseline_result.json` and `candidate_result.json` preserve the exact returned
JSON bytes with a full result when it fits, plus a bounded summary. Separate
compact summaries point to those files by SHA256. Combined result+summary bytes
are capped at16MiB per role and32MiB per pair. Summary stdout contains only
actions, counts, status and evidence references. Summaries explicitly count
omissions; they do not replace the complete result. Full evidence serialization
rejects cycles, nonfinite values, non-JSON mixed/sparse keys, a500000-node ceiling
or the byte cap and records an explicit full-result gap instead. UTF8 truncation
preserves character boundaries. Errors, timeout, mutation, missing input fields
and absent results remain explicit; a failed first role stops the pair.

The observed shop snapshots omit `shop_forecast`. That field stays absent:
the worker does not reconstruct hidden future shop information or declare a
missing mechanic qualified. A returned action can differ from the recorded live
action because this public export may not contain all runtime decision inputs.
Each receipt therefore records input gaps and remains a single dependent public
comparison, not an unseen holdout, source continuation, causal win proof or
terminal result.

`prepared/manifest.json` preserves the initial preparation. It is superseded for
adapter source hashes by `prepared/manifest_final.json`, which includes the final
UTF8 and combined output-cap tightening. The registration-input maps still point
to these same final source files; root registration freezes their current exact
hashes. No historical job allowance is renewed.
