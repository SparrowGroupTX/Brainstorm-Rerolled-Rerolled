# Brainstorm Rerolled Rerolled

See the [Brainstorm v2.10.0-alpha release notes](RELEASE_NOTES_2.10.0-alpha.md)
for the new reusable Perkeo/Mega Spectral index family, its exact scope,
validation record, and final performance measurements. The
[v2.9.0-alpha notes](RELEASE_NOTES_2.9.0-alpha.md) retain the original
exact-index results and seed-structure research, while the earlier
[v2.8.1-alpha notes](RELEASE_NOTES_2.8.1-alpha.md) remain available as the
previous optimization record.

Brainstorm searches Balatro seeds until every enabled criterion matches. Open
Balatro's settings and select the **Brainstorm** tab. Its content is split
across Search, Cards, **Jokers 1-2**, **Jokers 3-4**, **Joker 5**, **Estimate**,
and Advanced pages so every control stays on-screen.

## Joker occurrences and timing

Choose up to five Joker occurrences. The same Joker may be selected in multiple
slots; selecting a duplicate no longer clears an earlier slot. Every slot has
its own:

- Joker selector;
- **Any Edition** or **Negative** requirement; and
- appearance timing selector.

The preferred cumulative timings are **By End of Ante 2** through **By End of
Ante 8**. They accept any collectible appearance in the starting Charm pack or
the natural no-reroll shop/Buffoon timeline through that deadline. Legacy exact
Ante 2-4 timings remain available for reproducibility. A Legendary target is
generated by a Soul. A non-Legendary target in the starting Charm pack is
generated by Judgement. The search checks both usable Soul/Judgement selection
orders.

Distinct Joker targets remain an unordered AND search for compatibility. As
soon as any Joker name is repeated, all populated slots become one chronological
acquisition sequence. For example:

1. Perkeo - Starting Charm Pack
2. Blueprint - Starting Charm Pack or Charm Pack or Ante 2
3. Invisible Joker - Ante 1 Early or Ante 2
4. Invisible Joker - a later exact Ante

The search then requires Perkeo before Blueprint, Blueprint before the first
Invisible Joker, and the first Invisible Joker before the second. Repeated
Jokers can use cumulative deadlines, but each slot still consumes a different
chronological acquisition; one visible card cannot satisfy multiple slots. The
legacy **Charm Pack or Exact Ante 2** option remains restricted to a
non-repeated target because it is ambiguous for duplicate ownership.

### Selling and finding a second copy

Chronological duplicate searches model the normal Joker-pool restriction.
Without Showman, Brainstorm assumes an ordinary repeated Joker is sold at the
earliest point needed to unlock its next occurrence. Invisible Joker is
different: it must complete two blinds before its copy effect and sale route
are considered ready. Brainstorm ages it by completed blinds, then assumes it
is sold at the first eligible point when another Invisible is still required.

Initial shop stock and the two displayed booster types are generated before a
sale. Buffoon contents are generated when the pack is opened. Consequently, a
new copy may appear in a still-unopened same-shop Buffoon pack after the sale
animation finishes, or in a later natural shop. The duplicate timeline uses no
paid rerolls and assumes every displayed Buffoon pack is opened left-to-right.
If Showman is selected and acquired earlier in the sequence, later duplicate
Jokers may remain in the pool without selling the first copy.

The native search automatically follows the current run's stake (or the
selected profile stake when no run is active). On Black Stake and above,
Eternal shop and Buffoon-pack Jokers cannot be used as the assumed sale route
for a later duplicate. Perishable and Rental Jokers remain sellable, and
Invisible Joker keeps its normal Eternal exemption. Jokers created directly by
Soul or Judgement do not receive stake stickers, matching the game.

Ante labels follow the RNG ante used by Balatro. The shop after defeating an
Ante 1 boss therefore belongs to the Ante 2 window. Skipped blinds do not age
Invisible Joker.

## Card suit modes

The target-suit selector has three behaviors:

- **Any Suit** pools matching cards across all four suits.
- **Any One Suit** accepts any suit, but one individual suit must reach the
  full **Min Target Count** by itself.
- **Clubs**, **Diamonds**, **Hearts**, and **Spades** require that exact suit.

Card-count searches use the active deck's real starting composition. Normal
decks, including Plasma, have one card of every rank and suit; Abandoned omits
face cards; Checkered converts Clubs to Spades and Diamonds to Hearts. Only
Erratic generates 52 seeded random base cards.

## Multiple Souls

**Min Souls in Charm Pack** accepts 0 through 4 and checks natural Soul rolls
inside the starting five-card Charm-tag Mega Arcana pack. Vanilla Balatro
normally suppresses duplicate Souls, so Brainstorm narrowly lifts that
suppression for the matching filtered run and that Charm pack only. Other packs
and ordinary runs keep vanilla behavior.

A Mega Arcana pack still allows two selections. Up to four Souls can be shown,
but only two can be used unless another effect changes the pack's choices.

## Search behavior and performance

### Exact rare-route indexes

Brainstorm uses two exact-index families. The v2.10 family targets the broader
NaNEInf setup that motivated this release:

- The reusable **Charm/Perkeo/Mega Spectral parent** contains the complete
  Plasma Deck/Gold Stake population for an opening Charm route with one
  effective required Soul, Perkeo supplied by that Soul at any edition, and
  **Booster Pack Search** set to Mega Spectral Pack.
- Its **five-Joker child** adds exactly one each of Perkeo, Blueprint,
  Brainstorm, Baron, and Mime on the natural no-reroll timeline. Blueprint and
  Brainstorm must appear by the end of Ante 4; Baron and Mime must appear by
  the end of Ante 8. The stored baseline accepts any edition.

The Mega Spectral predicate guarantees the searched booster type only. It does
not guarantee Cryptid, Ankh, or any other particular card inside that pack.

The five-Joker child remains exact for a selected setup that makes its baseline
stricter. For example, a Negative edition, an earlier Joker deadline, a
voucher or Observatory deadline, card-count filters, and advanced filters can
only remove candidates. Every indexed candidate is therefore run through the
full active simulator before it can be returned. A later Joker deadline would
broaden the stored child predicate, so that query uses the reusable parent
instead. More than one effective required Soul, another deck or stake, a
different booster criterion, or Perkeo outside the starting Soul route uses an
older applicable index or the ordinary raw search.

The v2.9 family remains available for its original route:

- Perkeo and Invisible Joker both selectable from the starting Charm pack;
  and
- that same pair followed by another Invisible Joker in the exact Ante 2
  no-reroll timeline on Plasma Deck at Gold Stake.

The v2.9 parent is complete across all 15 supported vanilla decks and all
eight stake levels. Its later-timeline child is deliberately Plasma/Gold-only.

When a configuration logically implies an indexed predicate, the engine walks
the matching candidates in the same cyclic seed order as raw enumeration. The
most specific complete child is tried first, followed by its reusable parent
when needed. The estimator follows the same choice and identifies the selected
index in its output.

Payloads are bounded and checked for eight-byte alignment, ordering,
uniqueness, seed-domain range, record count, and a hard-coded FNV-1a content
fingerprint before a complete indexed miss is allowed to prove that a search
range has no result. Build-time manifests additionally record SHA-256 and
predicate provenance. If an asset is missing, damaged, disabled, outside its
declared scope, or not trusted as complete, Brainstorm safely retains the
ordinary raw fallback. A structurally valid but untrusted list may prioritize
candidates, but can never suppress that fallback.

The exact v2.10 record counts and measured indexed-versus-raw timings are kept
in the release notes so this README does not preserve stale benchmark figures.

**Observatory Deadline** accepts Ante 2 through Ante 8. The search requires
Telescope to be offered and acquired first, followed by Observatory no later
than the selected Ante. Delaying Observatory does not delay Perkeo's consumable
copies, so a later deadline can make a seed much easier to find without losing
early Eris duplication.

When an Observatory deadline is active, Voucher Search may be left at None or
set to Telescope (which is redundant but valid). Early Retcon cannot be combined
with an Observatory deadline because those two voucher routes cannot be
guaranteed as one playable purchase sequence.

Legacy-compatible distinct-Joker searches retain their original early windows.
Duplicate and later-Ante searches use the chronological no-reroll timeline
described above. Later Antes and Negative duplicate requirements are inherently
rarer and can take much longer.

The **Estimate** page can benchmark the currently selected configuration for
about one second. It reports a typical search time, a 90%-chance time, a broad
uncertainty range, and the measured seed-checking speed. An applicable complete
index is measured directly and labeled **Exact index** or **Indexed sample**,
including its candidate population and candidate-checking speed. Other common
configurations use matches from an exact raw sample. When a configuration is
too rare to produce an exact hit during that short benchmark, the page clearly
labels the result as a rough staged estimate and shows the sample evidence
behind it.

Estimates are probabilities rather than a countdown or guarantee. A particular
search can finish much sooner or much later, especially with Negative or
repeated Joker requirements. The result is kept only for the current session
and is marked out of date whenever a search setting changes.

Starting-Charm staged estimates reuse the already-validated Charm Tag instead
of treating it as a second independent tag roll, keeping their modeled rarity
aligned with the actual search route.

Cheap exact pack, tag, voucher, and deterministic deck checks run before the
larger Joker simulation. The engine reuses each worker's simulator, avoids
unneeded choice branches, rejects impossible timing combinations before the
search starts, and only enables the more expensive chronological matcher when
the selected criteria require it.

The chronological matcher skips stake-sticker RNG when Eternal status cannot
affect a later duplicate sale. When an Eternal-compatible repeated Joker does
need that decision, it preserves the exact Eternal poll while omitting unused
Rental and Perishable processing. This keeps Gold-stake duplicate behavior
exact while materially reducing later-Ante search work.

On supported x86 processors, exact scalar, AVX2, and AVX-512 implementations
are selected at runtime for the common opening Charm/Soul route, tag-only
searches, and the legacy Negative Blueprint filter. Every vector result is only
a necessary-condition gate: the ordinary simulator still verifies each rare
survivor before returning a seed. The Negative Blueprint gate also uses the
Joker's Rare roll when later Joker criteria would otherwise make survivor
verification expensive.

The old seeds-per-frame setting did not affect the native search and has been
removed from the menu. **Native CPU Mode** offers Balanced scheduling or
Maximum throughput. Maximum uses an aggressively benchmarked worker count (36
workers on the 16-core/32-logical-processor development machine) and may make
the game and desktop less responsive while a search is active. The common
starting Charm/Soul/Perkeo route is evaluated directly from compact seed state
before the general shop simulator, avoiding unnecessary maps, allocations, and
later Ante work for rejected seeds.

When a specific Legendary Joker is required, the AVX-512 opening gate now
checks that identity before doing Charm-tag and Soul work. This rejects roughly
80% of seeds at the cheapest useful point. A staged exact tag classifier also
uses only the random bits needed by almost every tag bucket and falls back to
the full calculation at the seven boundary prefixes where more precision is
required. Both optimizations preserve bit-for-bit Balatro RNG behavior.

### Reproducible optimized native build

Ordinary CMake builds remain portable. On the development machine, the tested
optimized build can be produced from PowerShell with:

```powershell
.\Immolate\tools\build_pgo.ps1
```

This performs a strict native GCC build, runs the exact-seed regression suite,
trains it on the literal and relaxed Plasma/Perkeo/Invisible/Observatory routes
plus multi-Soul, Negative Joker, and Erratic-deck workloads, rebuilds with the
captured profile, and runs the tests again. It never enables fast-math and
explicitly disables floating-
point contraction, because changing those operations changes Balatro's seeded
RNG results. The resulting DLL is machine-specific and is not installed into
the live mod automatically.

The trainer uses one thread and fixed, bounded seed ranges so profiles are
reproducible. The build script also stops if any profiled source changes between
generation and use, rather than consuming stale data.

For manual builds, use `BRAINSTORM_NATIVE_OPTIMIZATIONS=ON` and configure
`BRAINSTORM_PGO_PHASE` as `GENERATE`, then `USE`. Both phases must reuse the
same build directory and the same absolute `BRAINSTORM_PGO_PROFILE_DIR`; GCC
keys its counter files to the object paths. `OFF` is the default for both
optimization features. Set `BRAINSTORM_PGO_TRAINING_SCALE` to a positive
fraction (for example, `0.01`) only when smoke-testing the training executable;
the full profile should use its default workload sizes.

The active vanilla deck is simulated, including its initial deck and shop
effects. Modded decks and Challenge runs are rejected because their custom
Joker-pool restrictions are not represented by the seed simulator.
