# Certificate comparison: bounded design after read-only inspection

This is a design and cost estimate only. No source inspection, source component,
captured replay, new policy evaluation or runtime edit was performed. The exact
source callback timing and generation pool still require a fresh registered
mechanical inspection before implementation may claim source agreement.

## Existing support

`blind_start.lua` currently models ordered setting_blind callbacks for Dagger,
Burglar, Chicot and Marble. It explicitly rejects Certificate, Cartomancer,
Riff-raff and Madness. Marble's generated Stone card is appended to the playing
population and included in the paired shuffle, with four explicitly uncertain
front/composition samples. This is not the same operation as Certificate.

The C03 preserved transition proves one new Purple-sealed7 of Spades was added:
the first observed boss hand held nine cards, while nominal hand_size was eight.
That observation alone does not establish callback timing, all possible fronts,
seal weights, copied-Certificate ordering or interaction with other startup
Jokers. Reusing Marble's shuffle path would incorrectly risk placing the new card
in the remaining deck instead of the observed initial hand.

`shop_scoring.lua` can enumerate first-hand subsets for up to ten cards. Its
ordinary eight-card family has218 subsets; nine cards have381. It fixes one
executable pre-blind arrangement for supported startup projections and completes
every admitted composition world before publishing a profile.

`blind_finishing.lua` currently admits at most eight held cards, so a correct
nine-card Certificate opening would still have no whole-blind comparison.
It has two fixed policies, play-only and one targeted first nonclear discard;
later play candidates are bounded to32. A Purple discard with available
consumable capacity fails in `scoring.after_discard` unless its generated Tarot
identity is explicitly provided. No such identity may be invented.

## Smallest plausible complete sampled scope

Start with exactly one active, uncopied Certificate event and no other
creation/destruction/startup callback. Keep all current visibility, identity,
population, boss and cash guards. Defer copied Certificates and interactions until
their callback order has separate exact evidence; do not globally whitelist the
Joker as stable.

Use a separate first-draw-generation phase, according to the source timing once
verified. Preserve the same four root-fixed ordinary deck composition worlds on
both sides, then supply one explicit generated front/seal per world with a stable
synthetic identity. The complete admitted comparison includes every one of those
worlds; it is not an exhaustive random-outcome distribution or calibrated mean.
Sampling must include the seal classes without choosing ranks/seals to make a
particular captured state pass. Its mapping is deterministic from public
metadata, independent of the source seed or actual future draws.

Allow exactly one verified extra initial held card while nominal hand_size stays
eight. Use the exact first discard/play/refill transition; do not permanently
increase hand_size or silently remove a card. Later observations return to the
existing eight-card scope. If an admitted policy encounters unsupported Purple
generation, the entire comparative family remains unavailable. A separately
declared policy may avoid that unknown action using only the observed seal and
inventory, but must do so identically on every candidate and publish the omitted
action scope. It cannot fill in a favorable Tarot or mix successful worlds with
unresolved ones. Full Tarot-generation support is a separate, larger extension.

Do not treat unsupported endpoints as inferior to a supported Card Sharp. That
would bypass the exact complete-family rule which correctly stopped C03's
partial pack comparison. The generator and scoring candidate must both have
complete admitted mechanics before tactical ranking can replace the fallback.

## Cost estimate, not a measured benchmark

If a vanilla single-card family is52 fronts times four seals, exhaustive
enumeration crossed with four deck worlds and381 subsets requires316992 scores
for the Certificate opening alone. That already exceeds the existing50000 shop
budget. The assumed source support/weights need verification; this arithmetic
does not declare that whole family source-qualified.

Four explicit composition worlds, one fixed Joker order and one opening scenario
instead require4*381=1524 opening scores. A loose continuation upper bound for
four hands is4*(3*32+4 + 4*32+4)=928 scores: play-only uses its cached first play,
the targeted-discard policy may recompute all four plays. Total2452 per fixed
Certificate profile, excluding small non-score metadata work. An ordinary
eight-card counterpart is at most872+928=1800 under the same assumptions. Extra
layouts/scenarios/endpoints multiply these terms; the context must preflight the
actual full family and retain its50000 aggregate cap. The existing architecture
must not borrow an unlimited new budget for generation.

## Validation needed before a runtime slice

- Fresh mechanical source evidence for callback phase, generated card identity,
  allowed front/seal data, initial hand size/population and refill behavior.
- Synthetic exact tests for initial nine-card legality, first play/discard fill,
  all admitted generated branches, stable paired ordinary draws, input
  immutability, population conservation and unknown generation failure.
- Complete supported candidate-family tests: an unavailable Certificate branch
  still falls back as a whole; an ordinary scoring alternative can displace a
  generator only after both comparisons complete within50000 scores.
- A separately preregistered captured C03 comparison and later terminal attempt
  if root elects to spend fresh authority. Neither is performed by this note.

The separate nonlinear ranking issue remains: the generic comparison's fixed
-14 hurdle can make a2/4-to4/4 complete sampled clearance change negative when
mean capped progress was already close to one. A principled repair should use
complete survival/resource dominance and actual paid/action costs. A Card Sharp
weight boost selected because this run lost would not address the mechanism.
