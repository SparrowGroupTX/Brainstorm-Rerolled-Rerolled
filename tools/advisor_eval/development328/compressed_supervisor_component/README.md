# Prospective lossless stdout transport

Ready for root review. Copy `stdout_transport.py` alongside the root supervisor and apply `validation_cycle.patch` only before registering new jobs. The root supervisor, already frozen C01, and all existing P registrations/traces were left unchanged by this component. There is no new experiment allowance, reset path, search or source execution here.

New compressed C jobs must preregister the exact `stdout_transport.CONTRACT` as `metadata.stdout_capture`: gzip level1, members of at most65,536 decoded bytes,256MiB compressed file maximum and2GiB decoded stdout maximum, with SHA-256 of decoded bytes. The supervisor and helper must be frozen as `supervisor_source.py` and `stdout_transport.py`; metadata.supervisor_sha256 must match the running supervisor. Legacy registrations without this field retain their original raw transport. P jobs cannot opt into this C contract.

The existing serial OS lock, exclusive reservations/spent receipts, exact Python entrypoint/runtime bindings,180-second C cap and global one-use authority remain intact. A stdout thread drains the sole Python worker into concatenated standard gzip members. Complete captures round-trip every stdout/stderr byte, including control characters. A member is committed only if it fits both byte caps; capped/error/timeout captures retain an explicit valid prefix, count any read-but-unpersisted bytes, and do not claim the unseen tail. Both natural child exit and complete drainage must be observed within the same deadline. Forced-termination EOF does not establish capture completeness. Child and writer termination must be confirmed before another job can start. Total supervisor elapsed time remains in `elapsed_seconds`; capture time is separately reported as `capture_elapsed_seconds`.

Fifteen tests pass using dummy Python processes and in-memory byte streams in disposable temporary directories. Coverage includes binary/stderr round-trip, empty/exact-limit streams, compressed and decoded limits, timeout and late drainage, launch/reap/thread-start/compressor failures, transparent streaming reads, corruption/reader caps, strict entrypoints, an isolated fictional ledger's one-use receipts/OS lock, and total timing. The initial suite exposed a timeout EOF classification mistake, now fixed; `TEST_AUTHORING_01.json` preserves that failure. No real authority file or slot was accessed by tests.

`trace_sha256` and `trace_bytes` bind compressed storage; `decoded_trace_sha256` and `decoded_trace_bytes` bind the persisted decoded prefix. `stdout_capture_complete`, `stdout_eof`, `stdout_drain_completed`, `worker_reaped`, `capture_limit_reason`, `capture_errors` and read/unpersisted counts distinguish full data from incomplete evidence. A nonzero worker exit can have a complete captured stream while the experiment still remains an error. Byte caps, errors, timeouts and unsupported results never become wins.

Compression reduces storage demand; this component does not claim a runtime improvement or comparable C01-raw versus C02-gzip timing. Different policy bytes, source printing and read/compression overhead remain relevant.

# Audit-reader contract

Do not rewrite old traces or change their hashes. Resolve `record.trace_path` (new jobs) or `trace.log` (legacy), require the resolved path to stay inside the job directory, and verify stored bytes/SHA-256 against the record before decoding. Use `stdout_transport.verify_trace` to stream-verify the decoded count/hash for gzip jobs. For raw jobs, the existing stored count/hash is also the decoded count/hash. The2GiB decoded guard remains active; reader errors are evidence, not permission to skip records.

`open_trace(path)` is a binary streaming context manager that detects gzip magic and supports old raw files. `iter_chunks(path,max_decoded_bytes=...)` provides bounded decoded chunks; `verify_trace(path,expected_bytes,expected_sha256,...)` checks the complete decoded stream without loading it into memory. `iter_json_lines` is strict and bounded (default64MiB per JSON line), raising explicitly on malformed, truncated or oversized records. If a source trace contains non-JSON diagnostic lines, use `open_trace` or a bounded chunk/line parser and retain those error lines separately; never silently discard them. Standard gzip tools also support the concatenated members.

Completeness of a returned product action, supported mechanics, paired comparisons and terminal outcome must still be audited separately from transport integrity. A valid gzip hash proves byte preservation, not a supported action or a win.
