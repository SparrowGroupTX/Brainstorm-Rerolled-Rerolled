# Journal precision timing — detached candidate

Stage only `player_journal.lua` to `Brainstorm/Advisor/player_journal.lua` and `test_player_journal_timing.lua` to `tests/advisor_player_journal_timing.lua` after reviewing `manifest.json`. The production fixture loads only the production module. This package does not include the inactive journal optimization sketches from development323. It does not stage, install or modify runtime files itself.

Each enabled event retains its UTC `at` value and existing sequence behavior, and adds an event-entry `monotonic_seconds` anchor. The clock is the injected `deps.clock`, or `love.timer.getTime` when none was injected. It is sampled before observation, encoding and append. The number remains a full finite Lua number and uses the existing 17-digit JSON encoding. `monotonic_status` is `available` or `unavailable`; when absent, the numeric value is omitted and a bounded reason identifies an unavailable, failed, invalid or regressing clock. Clock failure does not fail logging or gameplay. Equal timestamps are valid. The last successfully appended valid anchor is retained only after append succeeds. These elapsed wall-clock values are meaningful within the process/session, not CPU time or a timestamp comparable across restarts.

Optional instrumentation resolves `A.performance` dynamically at event time. The only collector APIs called are `P:now()` and `P:record(label, seconds)`. Declared labels are `journal.observe`, `journal.encode`, `journal.append` and `journal.total`. Observation includes context acquisition, UTC formatting and entry construction. Append includes the entire existing archive writer, which performs catalog accounting, frame encoding/hashing, optional compression/decompression, append and exact readback. Total covers the event through the successful commit/rotation or the detected error, before the existing failure notice. Invalid measurements or failing collector calls are omitted without failing the event.

`J:timing(kind, details)` emits an ordinary event with explicit `context={}`. It never calls full snapshot observation, never invents a nested logger event and never clears collector data. Its encoding and append duration becomes known only after its bytes have been written, so those measurements belong to the *next* collector summary. The root collector must acknowledge only the measurements represented by an appended summary, preserving the metrics added during that summary's write. Failed summary appends must not consume measurements. No decision-performance object is added to `context.advice` here: the parent owns that final bounded summary API and runtime integration.

Opt-in behavior, snapshot redaction, callback arguments/returns/errors, action-sequence linkage, settled observation scheduling, archive format/rotation/readback, byte/event/storage limits and persistent retry protections are unchanged. The default unconfigured recorder remains off. No snapshots or extra clock reads occur for disabled events. This change adds precision to new records; it does not reconstruct timing absent from old logs.

Routine manufactured validation passed 105 new and 21 existing Lua checks. A detached runner also passed all 15 existing Python fake-filesystem/archive decoder tests plus one new precise timestamp/compact-summary compressed roundtrip test. No player log/save/profile, executable/archive source, captured state, source worker, search, game control or installation was used. No live CPU percentage, freeze cause or elapsed-time improvement is demonstrated. The original experimental cycle remains closed.
