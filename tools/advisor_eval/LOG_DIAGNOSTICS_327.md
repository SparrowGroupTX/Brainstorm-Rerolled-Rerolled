## Runtime repairs

Pack and blind decisions now run through the advisor's cooperative worker path. Blind routing receives the worker yield callback while preserving an explicitly supplied caller callback and unmodified caller options. Candidate order, completed comparisons, score allowances, freshness checks and input invariants remain. A short decision can complete during its first resume; the existing four-millisecond allowance is cooperative, not a hard bound on each operation.

A shared pure `snapshot.phase` classifier avoids repeatedly constructing full runtime snapshots in ready states outside decision phases. Other callers retain the same complete snapshot capture behavior, and product observation still captures the state needed to acknowledge a prior action at an unsupported endpoint. The journal's separate `public_snapshot` function redacts concealed identities for public export; internal snapshot capture is not that redaction boundary. Execution recaptures and worker-slice fingerprint checks remain intact. Manufactured fixtures compare complete yielded and synchronous decisions and verify waits, cancellation, stale-action rejection and nondecision capture avoidance.

The internal `fingerprint`, `before` and `after` strings were serialized state representations, not small opaque identifiers. Their canonical value sizes totaled 173,541,923 bytes in the selected observations, versus 123,509,508 bytes for `context.snapshot`; these are explanatory re-serialized value sizes, not an exact wire decomposition. More seriously, internal fingerprints could carry identities intentionally redacted from the public snapshot. Prospective auto-run export now records opaque SHA256 identity and byte-length metadata, with an explicit unavailable status when hashing fails, while retaining the full redacted public observation and the internal comparison strings used by the controller. This is a public-observation contract correction, not a claim to retain raw internal text losslessly. Existing logs and captured evidence remain unchanged and are not deleted or rewritten.

A bounded offline export-size comparison applied exactly that declared identity transformation to all 1,831 captured events: 951 identity fields changed, with all other decoded values verified unchanged. Using the same BRJ2 writer produced 5,085,667 stored bytes instead of 16,074,649 (68.36% smaller), and 130,016,334 expanded bytes instead of 303,399,440 (57.15% smaller). This measures the prospective format on selected existing data, not live post-install throughput, and does not replace or claim lossless reconstruction of old internal text. The original captured file hashes remained unchanged. `development327/archive_codec/prospective_export_size.json` records the 32.515-second measurement, bounded below its 45-second cap.

The product keeps the existing BRJ2 archive and decoder. A detached BRJ3 repeated-string design and its compatibility investigation remain preserved under `development327/archive_codec/` and `development327/context_reader/brj3_followup_deferred/`; they are not shipped. The root timing analyzer was restored to its exact pre-327 bytes after that investigation.

Preserving older logs does not make their raw internal fingerprint strings valid public development inputs. Future strategic postmortems must use the redacted `context.snapshot` and recorded time/action metadata, not infer concealed identities from old fingerprint payloads. Size accounting and hashes do not require that hidden-state interpretation.

## Context-safe tooling

`inspect_player_log.py` reuses `read_player_log.py` and `analyze_player_timing.py`. Its default JSON output is at most 16 KiB. Counts, timing, error signals, overlapping field sizes, repeated canonical snapshots and selected examples replace bulk payloads in model context. Every table counts omitted rows. Reported terminal labels are not converted into verified wins, repeated public states are not treated as hidden-RNG equivalence, and inter-event gaps are not classified as freezes without supporting measurements.

Each selected event has an exact input-file index, ordinal, sequence, stored byte interval and decoded-event SHA256. The separate extraction command requires the full input hash and writes at most 16 selected events / 4 MiB of original JSONL bytes to a new artifact. It validates the archive, never overwrites an input or existing output, and prints a bounded receipt instead of the event payload. A summary is an index, not a lossless replacement; exact information remains in the originals. Malformed timing semantics can be extracted for diagnosis if original JSON/archive integrity is valid; corrupt or incomplete archives are declined explicitly.

The copied-tail tooling proof covers only segments 000011–000014: 1,071 events / 172,716,754 expanded bytes produced a 16,001-byte index with 164 omitted table rows counted explicitly. It records 755 snapshots, 202 canonical distinct values and 553 repeated observations, representing 50,951,382 repeated canonical bytes. Those four captured inputs retained their hashes. The final tooling tests use manufactured data; no new external log read or gameplay experiment was performed by that component.
