# Nonempty Perkeo Planet copying and actual final-boss delivery

Detached candidate, prepared against installed309. Root owns integration, freeze,
full regression, install and exact-installed verification. No runtime file, source
worker, native binary, player save/profile, search, or live game was changed here.

## Problem and resulting behavior

Gold cargo comparisons previously admitted Perkeo only with an empty consumable
pool. Admitting a nonempty pool by Joker name would miss the immediate copies,
their Negative capacity/price, Observatory, and the opportunity to use Planets
before selecting the boss. In particular, a fixed hold-all/use-all rule misses
nonlinear cases. A synthetic Pair-level4 Observatory case with three Mercuries
has its strongest supported opening after exactly one use.

This candidate qualifies a homogeneous ordinary-Planet pool using exact observed
registry identity, constructor config, safe parameters, full copied ability,
empty-front base, prices, edition, and physical state. It projects the supported
physical Perkeo/Blueprint/Brainstorm callbacks on shop exit, including a legal
pre-exit copy arrangement. Newly produced Negatives remain in the same proved
copy class, so all sequential random choices from the growing whole inventory
produce equivalent relevant states. No random sample or future sort ID is guessed.

Each endpoint then enumerates all ordinary-used × Negative-used counts. This
retains all hold/use alternatives while treating Negative capacity loss separately.
The existing owned-consumable transition includes hand levels, Constellation,
usage history and last-used identity; cash and playing-card population must remain
unchanged. Equal scores/action counts prefer the extra ordinary capacity available
for Blue generation. The comparison does not claim or spend a future Blue reward.

Every candidate's full family is compared against all hold, incumbent, AND its own
alternatives using the same existing shop context. One fixed after policy must
preserve every compared world (and every Bell forced-card branch), with a minimum
25% opening margin. It never chooses a different use count or Joker layout by
future world. Its own family is included so fresh delivery can recompute a
dominating remaining suffix without storing an imagined state or hidden plan.

The actual first shop action is the existing paid buy/sell, or a real Perkeo
reorder, or leaving the shop. At the final blind selection, `gold_planet_policy`
compares the observed real inventory again without generating copies again. It
delivers one actual owned use, requests refresh, then a legal scoring reorder and
refresh, then the ordinary provider's exact Boss-selection action. Empty inventory
is a complete zero-use suffix, so using every Planet still delivers scoring order.
No projected identity is passed to Product Execute.

## Complete bounded scope

- Exact visible stable Gold row, complete eligible progress, final Vessel/Leaf/Bell
  only. Existing stable-retention rules remain; no Certificate, arbitrary generated
  Tarot, hidden hand, or unsupported source identity is added.
- Homogeneous ordinary or canonical Negative Planet copies. Same name alone is
  insufficient. Initially softlocked special Planets with extra source config
  decline rather than discarding that metadata. Mixed Tarot/Planet pools decline.
- At most eight post-exit cards, four immediate physical copy events, 25 complete
  after-use policies and 75 before references per endpoint comparison. Existing
  Gold limit of three offers/six owned Jokers/40 paid endpoints remains.
- The complete comparison uses the existing shared 50,000 shop-score allowance.
  Missing/partial evidence declines the whole recommendation. Final-blind delivery
  uses at most50,000 calls; failure work remains in decision totals even when a
  later ordinary provider returns early. Existing routing remains within its own
  bound and the ordinary140,000 ceiling is unchanged.
- Paid actions, pre-exit copy arrangement, Planet uses, and later scoring
  arrangement are counted in the projected action total. No sale/buy is credited
  with future income or an imaginary free slot. A sold Perkeo generates no copies.
- Ordinary non-Bell scalar receipts without a single fixed physical layout are
  insufficient. The production existing blind-finishing dependency supplies the
  fixed-layout receipt; Bell uses its existing complete forced-branch receipt.
- These are composition samples and exact bounded transitions, not whole-run
  wins, calibrated odds, human superiority, player achievements or a measured
  Completionist++ time improvement.

## Integration contract

New runtime files: `perkeo_inventory.lua`, `gold_planet_policy.lua`.
Existing runtime changes: `gold_goal.lua`, `gold_perkeo.lua`, `snapshot.lua`,
`decision.lua`. `integration.patch` is a narrow unified diff against the base hashes
in `integration_base_sha256.json`; rebase the decision non-hand hunks if root adds
an independent pre-search hand setup. No shop_scoring or phase_copy edits.

`runtime_wiring.patch` adds these three lines after loading gold_perkeo:

```lua
A.perkeo_inventory = module('perkeo_inventory')
A.gold_planet_policy = module('gold_planet_policy')
A.snapshot.perkeo_inventory = A.perkeo_inventory
```

The final-blind helper must be installed with its Gold admission; do not enable a
partial projection-only slice. Existing `A` supplies all dependencies, including
Gold, scoring, Bell, whole-consumable transitions, phase copy and blind finishing.
Any future original-source adapter must explicitly load both new modules and
attach `snapshot.perkeo_inventory`; old captured states without `copy_source`
remain unsupported. No unseen/source validation is claimed by this draft.

Install fixtures from `install_advisor_perkeo_inventory.lua` and
`install_advisor_gold_planet_policy.lua` into `tests/` with the `install_` prefix
removed. Their runtime paths are already transformed; wrapper checks validate the
exact transformed files without changing the actual runtime/tests directories.

## Synthetic verification

See `focused_report.json` for exact final artifacts, command, counters and timing.
The new inventory fixture has110 checks. The new integration fixture has125
checks and3,172 actual score invocations across independent synthetic cases.
It instruments the scorer itself, including internal after-play calls, and verifies
each whole context's actual calls against its charged count. The failure of the
initial proxy-only fixture counter was an instrumentation gap: internal after-play
calls used the real module, not the proxy. The final instrumentation covers both.

Covered cases include nonlinear one-use Observatory selection; ordinary capacity
tie-break; source/parameter/base/proof mismatch; mixed and growing Negative pools;
copy cycles/debuff/incompatible targets; copy price/discount/Astronomer; actual
use→reorder→Boss and consume-all→empty suffix; paid missing-Joker acquisition;
supported Perkeo retention against a fully projected sale; first-time offered
Perkeo qualification; uncertainty, incomplete worlds/layouts, unknown progress,
in-flight/hidden inventory, insufficient budget, and insufficient score margin.
Eight relevant legacy fixtures pass unchanged. No selected development snapshot
was replayed and no terminal worker was launched.
