# Static feasibility: narrowly permitting inert perishable expiry

Date: 2026-09-16. Pinned Jackdaw: `92df18c27e26e6d324132942905e41242e4e24bf`. This is a proposal, not an implemented relaxation or engine qualification. No episodes, original-source execution, or manufactured tests were run for this follow-up. The current overlay remains unchanged.

**Operational decision: KEEP THE CURRENT EXPIRY CENSORS.** The parent review explicitly declined implementation: the coupled boundaries below need targeted source validation before the exception could be represented as a faithful repair. T02 continues under its original frozen limits; no retroactive eligibility changes or extra experiments are authorized by this note. The current source-worker budget is zero.

**Static feasibility conclusion:** a key-only exception is unsafe. The 15 canonical ordinary flat-scoring Jokers below offer a plausible narrow candidate, restricted by a persistent companion-row and consumable contract. The reasoning concerns the expiration transition and its immediate downstream debuff consequences; it is not a completed source-equivalence proof. It does not establish general Gold Stake equivalence or actual sticker awards. Keep all existing unsupported-state boundaries.

## Proposed supported keys and exact guards

Expiring-card allowlist:

```
j_joker
j_jolly j_zany j_mad j_crazy j_droll
j_sly j_wily j_clever j_devious j_crafty
j_greedy_joker j_lusty_joker j_wrathful_joker j_gluttenous_joker
```

`j_gluttenous_joker` is the actual catalog spelling. The proposal does not include Misprint, Banana effects, Golden Joker, passive Jokers, copy Jokers themselves, or the Legendary anchors as permitted **expiring** cards.

Apply the exception only if every condition holds, and recheck while any permitted near-expired/expired card remains owned:

* The known pinned engine plus declared overlay is in use; normal Red Deck / Gold Stake, no challenge or modified lifetime. Validate relevant source hashes, including handlers/lifecycle/consumable/economy code and center metadata used by the new contract. A changed dependency must not silently inherit the exception.
* Each expiring card's key, name, set (`Joker`), effect and static scoring configuration agree with its pinned center. Require ordinary edition (`None`), no seal, `h_size == 0`, `d_size == 0`, no consumable identity/flag, no eternal, `perma_debuff`, or queued Negative removal. Check integer tallies without Boolean coercion, and agreement of the attribute/ability tally fields. Tally 0 requires `debuff is True`; malformed or negative values are unsupported. Keep the existing permanent-debuff latch.
* The entire owned companion row is drawn only from those 15 keys plus `j_perkeo`, `j_yorick`, `j_burnt`, `j_blueprint`, and `j_brainstorm`, with matching names/sets/effects and zero passive fields. For the first implementation, require ordinary editions/no seals across this row as well. Anchor scaling fields may evolve through normal gameplay; do not reset them. The anchors/copies/Burnt have no end-of-round or dollar-bonus effect in these contexts. Any nonallowlisted expiring card still censors. A newly acquired companion outside this row makes the exception unavailable before the next observation or terminal credit.
* Require candidate-native rental representation: a Boolean top-level flag and absent/false `ability.rental` throughout the owned row. Do not drop rental charges on expired cards. No passive-modifying companion is permitted under the exception; existing non-expiry passive-debuff guards remain in force.
* Keep known unsafe consumables out of the decision state while this exception is active: `c_wheel_of_fortune`, `c_ectoplasm`, `c_hex`, and conservatively `c_ankh` in owned `consumables`, `shop_cards`, or `pack_cards`. Censor the whole episode before action generation/use, not merely remove an action. Recheck after pack/shop generation and inventory mutations. Hidden identity inspection, if needed for this audit, must only truncate the whole episode and never shape policy features/action masks.
* Continue the ordinary perishable-expiry censor for every state that fails the contract, including a permitted expired card later receiving an edition or entering a broader companion row. Preserve existing Mime, passive-debuff, nondefault lifetime and terminal-win checks. No reward is earned merely because expiry was admitted.

This is intentionally more restrictive than the set of cases that might be correct. It gives a small reviewable exception instead of silently treating every flat effect in every surrounding state as equivalent.

## Why the downstream guards are necessary

**Edition consumables:** original [card.lua:4209](C:/Users/trevo/Documents/GitHub/Brainstorm-Rerolled-Rerolled/tools/advisor_eval/runs/chicot_order_source1/source/card.lua:4209) fills Wheel/Ectoplasm/Hex pools with all editionless Jokers, including debuffed cards; original [use path](C:/Users/trevo/Documents/GitHub/Brainstorm-Rerolled-Rerolled/tools/advisor_eval/runs/chicot_order_source1/source/card.lua:1466) samples that pool. Candidate [can-use](C:/Users/trevo/Documents/GitHub/Brainstorm-Rerolled-Rerolled/tools/advisor_eval/development355/external/jackdaw/jackdaw/engine/consumables.py:442), [Wheel](C:/Users/trevo/Documents/GitHub/Brainstorm-Rerolled-Rerolled/tools/advisor_eval/development355/external/jackdaw/jackdaw/engine/consumables.py:733), [Ectoplasm](C:/Users/trevo/Documents/GitHub/Brainstorm-Rerolled-Rerolled/tools/advisor_eval/development355/external/jackdaw/jackdaw/engine/consumables.py:1122) and Hex filter out debuffed Jokers. An expired plain Joker changes both legal availability and random target distribution. A guard on its own key cannot catch this. Ankh also copies card bookkeeping into a new identity; keep it outside the first exception rather than assume lifecycle equivalence from deepcopy.

**Other Jokers:** source [Swashbuckler tally](C:/Users/trevo/Documents/GitHub/Brainstorm-Rerolled-Rerolled/tools/advisor_eval/runs/chicot_order_source1/source/card.lua:4240) includes every other owned Joker's sell cost. Candidate [Swashbuckler](C:/Users/trevo/Documents/GitHub/Brainstorm-Rerolled-Rerolled/tools/advisor_eval/development355/external/jackdaw/jackdaw/engine/jokers.py:1961) incorrectly excludes debuffed companions. Thus even ordinary flat expiry changes later scoring under an unqualified whole-inventory effect. The strict companion row excludes this and avoids having to audit all 150 handlers in this bounded refinement.

**Copy ordering:** a Blueprint/Brainstorm resolving to one of the allowed flat cards returns no end-of-round result whether the target has just expired or has not yet been expired by the batched candidate. Resolving to one of the supported anchors also has no effect in that context. The physical card remains in the row, so neighbor/leftmost identities and counts do not change. Later scoring correctly observes the common final debuff latch and does not copy an expired target.

**After removal:** selling an expired ordinary flat card reverses no passive/edition state in either implementation. Its absence correctly removes its possible sticker identity. This does not generalize to Negative or passive cards.

## Stronger teacher from the current advisor

The repository's current advisor is a more appropriate initial teacher than the prototype's simple handcrafted heuristic for the states it has source-grounded, tested support. This is a scope claim, not evidence that it is globally optimal or that every published recommendation is correct. Improving the teacher/data bridge and simulator fidelity should precede interpreting a larger network as a better player.

1. **Reuse the authorized public journal observations.** [player_journal.lua](C:/Users/trevo/Documents/GitHub/Brainstorm-Rerolled-Rerolled/Brainstorm/Advisor/player_journal.lua:298) publishes a detached redacted snapshot and `advice.action`. Its `advice.status == 'current'` requires the bound game, publication generation and snapshot fingerprint to match. Select only those records for advisor imitation; stale/computing/unavailable actions are not valid labels for the associated observation. Bind labels to the exact version, seed/opening, sequence, phase and observed target mask. No fresh game/source execution is needed to parse already authorized artifacts.
2. **Keep teacher, behavior and outcome separate.** Advice is a recommendation; a recorded user action is behavior; a settled state is a transition; an original award receipt is an outcome. Do not infer that the user followed advice, that a first settled observation completed every event, or that `won_field` proves an award. The journal explicitly calls out the settled-observation limitation. Use matching action receipts where available; exclude uncertain transitions from value targets.
3. **Lossless public action mapping first.** Translate hand indices/order, Joker reorder, target lists, shop/pack identity and consumable use into the learner's action schema for the same snapshot. If the learner cannot express the exact legal teacher action, mark it unrepresentable and count coverage; do not relabel a nearest candidate as the expert. Never resolve a hidden card identity or future shop from the seed. A remembered public inventory may be used only through the established visible-information contract.
4. **Behavior cloning before RL.** Learn phase-aware advisor action likelihood on represented current recommendations, balanced across hand/discard/shop/pack/consumable/reorder phases. Include the observed 91-missing mask; the five engine anchors are already complete. Group train/validation splits by whole run and seed/opening family so neighboring snapshots cannot leak across them. Measure exact action agreement and mapping coverage by phase; agreement alone is not gameplay strength. The public journal omits full candidate families, so it does not provide genuine soft policy distributions or counterfactual values to distill.
5. **Use established analytical targets carefully.** When recorded source-grounded score bounds, copy plans, acquisition/retention reasons or verified terminal receipts exist, attach their stated scope/confidence as auxiliary targets. Do not invent those fields from display text or promote a forecast into an award. A newly recomputed advisor teacher over public snapshots would need a separate bounded local-data job; it must not initialize original-source games under the current zero source-worker budget.
6. **Fine-tune only on supported transitions.** Preserve the original teacher checkpoint/control, then use fresh GPU BF16 updates with explicit simulator fidelity labels and the new-distinct-sticker proxy. Unsupported episodes cannot become false loss/value targets. Compare the learned policy against the current advisor on the same public observations and eventually the same qualified Red/Gold opening distribution; preserve full started-run accounting.

The immediate limitation is trustworthy terminal experience: an engine that censors most runs cannot establish the intended Gold-sticker return, regardless of model size. T02 can still provide optimization, representation and throughput diagnostics within its declared limits. It cannot establish that the new agent outperforms the existing advisor or earns actual stickers.
